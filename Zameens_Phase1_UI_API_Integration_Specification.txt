1. Integration Rules & Conventions
* All JSON field names use camelCase. Database column names may remain snake_case internally.
* All IDs exposed to clients are UUID strings unless explicitly documented otherwise.
* Dates/times are ISO-8601 strings in UTC, for example 2026-08-10T09:15:00Z. UI converts to local time.
* Money is sent as integer minor units (paise). Example: ₹4.25 Cr = 4,250,000,000 paise.
* Area can be entered in the selected unit, but normalizedAreaSqft is calculated by backend and is read-only.
* Access token is sent in Authorization: Bearer <token> for protected APIs.
* Accept-Language may be sent as en, hi, mr, gu, pa, te or ta. Canonical backend data remains language-neutral where possible.
* UI must use master IDs/codes returned by master APIs; do not hard-code land types, area units, document types or amenities.
* For file upload, UI uploads directly to cloud storage using signed URLs and then calls the corresponding complete endpoint.
* For list endpoints, the default pagination contract is page + limit. Unless documented, page defaults to 1 and limit to 20.
* Fields marked read-only must never be sent by UI in create/update requests.

1.4 HTTP status usage
Status
	Use
	200
	Successful read/update/action.
	201
	Resource created.
	204
	Successful delete with no response body.
	400
	Malformed request/business validation.
	401
	Missing/expired authentication.
	403
	Authenticated but not permitted.
	404
	Resource not found or not visible to user.
	409
	Conflict/duplicate/invalid lifecycle transition.
	422
	Field validation failure where framework uses 422.
	429
	Rate limit / OTP throttling.
	500
	Unexpected server error.

8. Frontend Integration Guidance
8.1 Loading, empty and error states
* Do not interpret an empty data array as an API error. Use meta.total = 0 for empty list state.
* For 401, attempt the agreed refresh flow once, then redirect to login if refresh fails.
* For 403, show permission-specific state; do not treat as not-found.
* For 409 lifecycle errors (e.g. trying to edit a sold listing), refresh the resource and show backend error.message.
* For validation errors, bind error.details[].field to the matching form field when possible.
* Disable duplicate submit buttons while POST/PATCH/action API is in flight.
* For payment, UI success is provisional until backend verification/webhook marks payment/order paid.
8.2 Form implementation rules
* Use IDs returned by master/location APIs. Send the ID, not only display labels.
* Persist add-property progress after each wizard step using the relevant PUT/PATCH endpoint.
* Do not calculate canonical area, verification score, premium state or listing lifecycle on frontend; render backend values.
* Price inputs can be displayed in lakhs/crores but must be converted to integer paise before API submission.
* Exact property coordinates may be intentionally hidden in public responses. UI must respect showExactLocation/public location precision.
* Use uploadUrl only for direct storage upload. Never persist it; it expires. Persist media/document IDs returned by complete endpoint.
